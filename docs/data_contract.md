# Data Contract (draft)

All modules agree on these formats. If a field needs to change, update this file
in the same PR and tell the team. `building_id` is the join key everywhere.

Conventions:
- Coordinates are WGS84 (EPSG:4326), GeoJSON order `[lon, lat]`.
- Times are ISO 8601 with the Arizona offset, e.g. `2026-10-12T14:30:00-07:00`.
- Walking times are in seconds.

## `data/buildings.geojson`
Point features, one per building.

| property | type | notes |
|---|---|---|
| `building_id` | string | ASU building code (`BLDG_CODE`), e.g. `MU`, `COOR`. Unique here: source records sharing a code are merged |
| `name` | string | display name |
| `aliases` | string[] | other names, the code, and facility numbers, used for matching event locations |
| `address` | string | street address |
| `bldg_numbers` | string[] | ASU facility numbers, e.g. `["026A","026B","026C"]` |
| `campus` | string | `MC` = Tempe |

Generated by `pipeline/buildings.py` from the ASU Facilities ArcGIS layer.

## `data/events.geojson`
Point features, one per event occurrence.

| property | type | notes |
|---|---|---|
| `event_id` | string | unique |
| `title` | string | |
| `start` | string | ISO 8601 |
| `end` | string | ISO 8601, null if unknown |
| `building_id` | string or null | null if the location could not be matched |
| `location_raw` | string | original location text |
| `category` | string | e.g. `academic`, `social`, `career` |
| `url` | string | source link |

## `data/pois.geojson`
Point features for coffee, food and study places. **Generated** by `pipeline/match_pois.py`, do not edit by hand.

Two sources go in (for now nothing from OSM is used, see `OSM_KEEP` in `pipeline/match_pois.py`; the page shows ASU dining on the Tempe campus):
- `data/source/pois_osm.geojson`: places from OpenStreetMap (Cade's extraction, `data/source/osm_amenities_raw.geojson` is the raw one).
  The script gives each the nearest building.
- ASU dining on the Tempe campus, checked by hand: `data/source/campus_dining.csv` (venue, building) and
  `data/source/campus_dining_hours.txt` (weekly hours). The building comes from the list. A row with an empty
  `building_id` is not on the page until someone fills it in.

| property | type | notes |
|---|---|---|
| `id` | string | unique: `osm_node_...`, `osm_way_...` or `dining_...` |
| `name` | string | |
| `category` | string | `coffee`, `food` or `study` |
| `building_id` | string or null | OSM: the nearest building (utility buildings are skipped), the place is next to it, not necessarily inside. ASU dining: the building it is in |
| `building_dist_m` | number | OSM: distance to that building point, more than 60 m is a weak guess. ASU dining: 0 |
| `hours` | object or null | see below. null = not known (a few dining venues, and the OSM places if they are brought back) |
| `source` | string | `osm` or `asu_dining` |

`hours` is `{"mon": [["07:30","21:00"]], "tue": [], "wed": null, ...}` for mon..sun:
a list of `[open, close]` = open in those ranges, `[]` = closed all day, `null` = not known.
A close time can pass midnight and is then written past 24:00 (`"26:00"` = 2:00 AM the next day).
The hours table (checked by hand) is read as it is: `Closed` = `[]`, `No data` = `null`.

The gap page uses a place as "on the way" when going through its building adds at most 2 minutes of walking
(`matrix[A][building] + matrix[building][event] - matrix[A][event]`), the detour fits in the time to spare, and the
place is not known to be closed when you get there. All the places in one building are one stop.

## `data/walk_matrix.json`
```json
{ "MU": { "HAYDN": 240, "LIB": 410 }, "HAYDN": { "MU": 240 } }
```
`matrix[from][to]` is the walking time in seconds. Missing pair = not reachable.
`matrix[x][x]` is `0` (same building). The matrix is symmetric.
Generated by `pipeline/network.py` from OSM walkways, at 1.34 m/s (about 4.8 km/h).
The walk from the entrance to the nearest path is included.

Walks start and end at the building entrance in `data/building_entrances.json` (centroid if there is none).

`data/building_entrances.json` (made by `pipeline/entrances.py`, run before `network.py`): `{building_id: {"lon", "lat", "source"}}`. `source` is `manual` (checked by hand, `data/manual_entrances.json`), `osm_main` / `osm_entrance` (a door tagged in OSM), `asu` (ASU's entrance points, `data/source/asu_accessible_entrances.json`, surveyed in 2020), `outline` (the point on the OSM outline closest to a path, a guess) or `centroid` (no outline found). Tried in this order.

Also generated by `pipeline/network.py`:
- `data/building_snaps.json`: `{building_id: {"lon", "lat", "snap_m"}}`, where each building touches the walking network and how far its start point (entrance) is from it (meters).
- `data/walk_network.geojson`: the walking network as LineStrings, for checking and drawing.

## User schedule (browser localStorage, key `schedule`)
```json
[
  { "course": "GIS 530", "days": ["mon", "wed"], "start": "13:30", "end": "14:45", "building_id": "COOR" }
]
```
`days` uses `mon`..`sun`; `start`/`end` are local campus time (`HH:MM`).

## `data/event_buildings.csv`
Links each event occurrence to a building. Generated by `pipeline/match_events.py`.

| column | notes |
|---|---|
| `nid`, `start` | together identify the event occurrence (same as in `asu_events.csv`) |
| `building_id` | empty if not matched (online, off campus, or not on Tempe campus) |
| `match` | `name`, `address` or `nearest` |
| `dist_m` | distance from the geocoded point to the building, meters |
| `review` | `check` (nearest match, unsure) or `far` (point is >250 m away, probably a geocoding error) |
